# Google Apps Script／試算表串接設定

## 已經預備好的內容

- EnglishWord 與比賽後台：登入後出現「Google 試算表串接」與「檢查 Google 連線」。檢查不新增測試資料。
- EnglishWord：啟用後，原本 `/api/stats` 改讀寫 Google 試算表，不再為瀏覽次數寫入 D1。
- 測驗開始紀錄：可選擇同步到試算表，只同步已通過每日額度檢查的測驗。屬於盡力同步，不是保證送達的稽核紀錄。
- 主站及比賽站：頁尾顯示瀏覽次數，透過同網域 `/api/stats` 讀取 `{ views }`。隱藏分頁等到可見才請求，同頁只請求一次，不自動重試；比賽管理頁不計次。
- 不提供公開任意追加、修改、刪除試算表的 API。單字、比賽內容、登入及每日 20 次測驗的強制限制仍留在 D1。

正式環境已有 Google 網頁應用程式及加密連線設定；實際啟用狀態應以正式後台／Worker 狀態為準。既有 D1 內容不搬移、不刪除。下方是可重用的設定步驟，不表示現有帳號尚未完成設定。

## 1. 建立一份專用且不公開的試算表

自行在 Google 試算表建立空白文件，保留私人分享設定，**不要發布到網路，也不要設為知道連結的人可編輯**。

複製網址中 `/d/` 與 `/edit` 之間的 ID，例如：

```text
https://docs.google.com/spreadsheets/d/這一段就是試算表ID/edit
```

從「擴充功能 → Apps Script」開啟綁定專案，把同目錄 `Code.gs` 的完整內容貼到 `Code.gs`。
在專案設定開啟顯示資訊清單檔案的選項，把 `appsscript.json` 換成同目錄版本。
程式僅要求試算表權限，不需要啟用 Sheets API、不需要 Google Cloud 付費方案。

## 2. 設定 Script Properties

在 Apps Script「專案設定 → 指令碼屬性／Script Properties」新增：

| 屬性名稱 | 值 | 是否必填 |
| --- | --- | --- |
| `SPREADSHEET_ID` | 上一步的試算表 ID | 是 |
| `BRIDGE_SECRET` | 安全亂數產生的 **64 位十六進位字串** | 是 |
| `MAX_EVENTS_PER_DAY` | 預設 `1000`，可設 `1`～`2000` | 否 |
| `MAX_TOTAL_EVENTS` | 預設 `10000`，可設 `1`～`20000` | 否 |
| `BASELINE_ENGLISHWORD_VIEWS` | 切換前的 EnglishWord 瀏覽總數，預設 `0` | 否 |
| `BASELINE_MAIN_VIEWS` | 主站既有瀏覽數，預設 `0` | 否 |
| `BASELINE_COMPETITIONS_VIEWS` | 比賽站既有瀏覽數，預設 `0` | 否 |

可以在自己的終端機執行 `openssl rand -hex 32` 產生 Secret。不要把 Secret 貼進對話、原始碼、試算表儲存格或公開網站。

在 Apps Script 上方函式選單選取 `setup`，手動執行一次並授權。
它只建立 `Events` 分頁／標題和必要空白列，保留其他分頁與既有紀錄，不會清空文件。
`Events` 是防重送與額度判斷的紀錄表，不要手動改欄名、插入公式或刪改紀錄。
`day_taipei` 是台灣日期識別值（文字 `YYYY-MM-DD`），不是試算表日期型別；程式會在每次新增前固定該格為純文字，避免自動轉型使下一次讀取遭拒。既有格式異常應先核對原始時間，再只修正相應欄位，不清空紀錄或放寬檢查。

## 3. 部署 Script

「部署 → 新增部署 → 網頁應用程式」：

- 執行身分：**我／部署者**。
- 存取權：**任何人**，讓網站伺服器能傳送 POST，不需要訪客登入 Google。這只公開程式入口，並非公開試算表；程式內仍要求 HMAC 簽章。
- 複製以 `/exec` 結尾的部署網址；不要使用 `/dev` 測試網址。
- 若 Workspace 管理政策不允許匿名網頁應用程式，先維持停用，不要改公開試算表來繞過限制。

網址與 Secret 都只交给 Cloudflare 後端，不放前台。直接用瀏覽器開 `/exec` 顯示 `SIGNED_POST_REQUIRED` 是正常防護，不是部署失敗。
每次修改 Script 程式後，要到「管理部署」選擇新版本再更新；只儲存編輯器不會更新 `/exec`。

## 4. Cloudflare 設定

在需要啟用的專案 **Production** 環境設定：

| 設定名稱 | 類型 | 值 |
| --- | --- | --- |
| `GOOGLE_SHEETS_URL` | Secret | 上一步的 `https://script.google.com/macros/s/…/exec` |
| `GOOGLE_SHEETS_SECRET` | Secret | 與 `BRIDGE_SECRET` 完全相同 |
| `GOOGLE_SHEETS_ENABLED` | 文字變數 | 先維持 `0`，測試成功再改 `1` |
| `GOOGLE_SHEETS_LOG_QUIZZES` | 文字變數，只用於 EnglishWord | 同步測驗紀錄才改 `1`，預設 `0` |
| `GOOGLE_SHEETS_LEGACY_VIEWS` | 文字變數，只用於 EnglishWord | 切換時保留的舊瀏覽數差額；預設 `0`，後台檢查會給建議值 |
| `D1_STATS_READ_ONLY` | 文字變數，只用於 EnglishWord | 經確認的短暫切換期間設 `1`，只讀舊計數、不新增瀏覽；完成後設回 `0` |

對應專案：

- EnglishWord：Pages 專案 `englishword`，正式分支 `production`。
- 比賽後台連線檢查：Pages 專案 `competition-board`，正式分支 `main`。
- 主站／比賽站瀏覽計數入口：Worker `pjmi-network-guard`。與 Pages 是不同部署，需獨立填入同一組設定。

先在 EnglishWord 與比賽後台按「檢查 Google 連線」。比賽自訂網域的後台會同時驗證共用 Worker 密鑰；未登入、跨來源或檢查失敗不會呼叫共用入口。EnglishWord 會額外以簽章讀取 Google 現有瀏覽數，與 D1 總數比較，回報保留基準；不新增測試事件。成功只表示部署網址、簽章和 `Events` 表正確，**不會自動開啟串接**。
再將對應專案的 `GOOGLE_SHEETS_ENABLED` 改成 `1` 並重新部署，使設定生效。
使用本機 Wrangler 部署者，必須同時把相應 `wrangler.toml`／`wrangler.jsonc` 中的開關改為 `1`，否則後續部署會把它重新設回 `0`；Secret 不寫進設定檔。

如需用 CLI 設定 Pages Secret：

```sh
wrangler pages secret put GOOGLE_SHEETS_URL --project-name englishword
wrangler pages secret put GOOGLE_SHEETS_SECRET --project-name englishword
```

比賽後台將專案名稱改為 `competition-board`；主站 Worker 在 `network-guard` 目錄執行：

```sh
wrangler secret put GOOGLE_SHEETS_URL
wrangler secret put GOOGLE_SHEETS_SECRET
wrangler deploy
```

主站及比賽正式網址的 `/api/integrations/google-sheets` 只提供開關狀態，不公開 Secret、Google 部署網址或試算表 ID。
Google 端可共用同一份試算表，`site` 分別記錄 `main`、`competitions`、`englishword`。

## 寫入防護與限制

- 每次後端呼叫都有 HMAC-SHA256 簽章、5 分鐘時效及 request ID；Google 回應也有簽章，網站不採信未驗證資料。
- 寫入採事件 ID 去重，同一事件重送不再新增，重送時改內容也會被拒絕。
- 所有寫入先取得 Script Lock，額度檢查和新增列在同一把鎖內完成，避免同時請求超限。
- 瀏覽事件：同一 IP **或**裝置每 30 分鐘最多計一次，每個站點每天最多 20 次；不是精確獨立訪客數。清 Cookie 不能繞過同一 IP 的限額。
- 測驗紀錄：同一 IP **或**裝置每天最多 20 筆；網站自身的 D1 限制仍是實際測驗授權依據。
- 所有站共用 Google 每日新增上限，台灣時間 00:00 換日；總筆數滿額後停止新增，不會自動刪除歷史。
- 只存每日輪替的 HMAC 身分摘要、站點及測驗題型；不傳送原始 IP、Cookie、email、密碼、答案、Google 權杖或任意文字。
- 網站快取只儲存彙總數字，不快取身分 Cookie。Google 回應有 16 KB 上限與 8 秒逾時；只接受 Google 指定回應網域的跳轉。
- Google 斷線／限額時，瀏覽統計暫時不可用，**不回退到 D1 增加写入**。測驗紀錄同步失敗不影響已通過 D1 授權的測驗，也不自動大量重試。
- 不會自動備份、刪除或輪替試算表。接近總筆數上限時，先保存原文件，再安排新表與基準數切換；不要在當天直接清空紀錄重置防護。

## 切換前後確認

1. 停用時原網站正常，後台顯示尚未設定／未啟用。
2. 管理者測試連線成功，試算表沒有新增事件列。
3. 經管理者同意，短暫設 `D1_STATS_READ_ONLY=1` 並部署，保持顯示旧總數但不增加。從後台檢查取得建議差額，填入 `GOOGLE_SHEETS_LEGACY_VIEWS`，再啟用 Google 並設回 `D1_STATS_READ_ONLY=0`。這段窗口可能漏計瀏覽，網站、題庫與測驗額度不受影響。不要同時把相同舊總數加到 Script Properties 基準與後端差額，避免加算兩次。
4. 啟用後 `/api/stats` 回應 `storage: "google-sheets"`，正常載入產生一筆 `view`，重載不重複新增。
5. 同步測驗需另開 `GOOGLE_SHEETS_LOG_QUIZZES=1`；成功開始才新增 `quiz`，20 次限制仍有效。
6. 將 `GOOGLE_SHEETS_ENABLED` 改回 `0` 並部署可停用 Google。D1 舊資料一直保留，但兩邊的瀏覽計數不會自動合併。

## 不是無限流量或 DDoS 防護的替代品

試算表串接可以隔離瀏覽計數的 D1 寫入並限制新增資料量，不能保證網站或 Google 入口不被 DDoS。
Apps Script 有每日服務配額及同時執行限制；不合法請求即使沒寫入試算表，仍可能消耗 Google 執行資源。
部署 URL 應當保持在後端；現有 Cloudflare 國家／VPN／Tor 防護繼續保留。
此方案不開通付費服務，但 Google 和 Cloudflare 免費額度不是無限，也不適合高流量或不可遺失的紀錄。
